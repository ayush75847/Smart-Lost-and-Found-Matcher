# 7. TOPIC 2: SET THEORY

Implement Jaccard Similarity using actual Python sets.

### Formula

J(A, B) = |A ∩ B| / |A ∪ B|

Example:

A = {black, leather, wallet, zipper}

B = {black, leather, wallet, small}

Intersection:

A ∩ B = {black, leather, wallet}

Union:

A ∪ B = {black, leather, wallet, zipper, small}

Therefore:

J(A, B) = 3/5 = 0.60

### Implementation

Create a reusable Python function:

`jaccard_similarity(set_a, set_b)`

Requirements:

* Handle empty sets.
* Remove irrelevant stopwords.
* Normalize text.
* Return similarity between 0 and 1.
* Display intersection and union.

When both sets are empty, treat similarity as unavailable rather than automatically assigning 100%.

### Visualization

Create an interactive set comparison panel.

Display:

* Attributes unique to A
* Common attributes
* Attributes unique to B
* Jaccard similarity percentage

Use a Venn-style diagram or clearly separated set visualization.

# 8. TOPIC 3: HEURISTIC REASONING

Implement a weighted similarity scoring algorithm.

### Default Weights

| Attribute   | Weight |
| ----------- | -----: |
| Category    |    25% |
| Item Name   |    20% |
| Color       |    15% |
| Brand       |    10% |
| Location    |    15% |
| Date        |     5% |
| Description |    10% |

Total = 100%.

### Mathematical Formula

S = 0.25C + 0.20N + 0.15Co + 0.10B + 0.15L + 0.05D + 0.10T

Where:

* C = Category similarity
* N = Name similarity
* Co = Color similarity
* B = Brand similarity
* L = Location similarity
* D = Date compatibility
* T = Description similarity

Each attribute similarity lies between 0 and 1.

Final matching score:

Score = S × 100

### Requirements

Implement the actual formula in Python.

Allow users to adjust weights in the Algorithm Lab.

Normalize weights when necessary.

Handle missing attributes consistently.

For missing optional attributes, exclude unavailable comparisons from the weighted average and renormalize the remaining weights. Display the percentage of total attribute weight for which evidence was available.

This prevents missing information from being mistaken for a confirmed mismatch.

### Score Interpretation

* 85–100: Strong similarity
* 65–84: Moderate similarity
* 40–64: Weak similarity
* Below 40: Low similarity

These are heuristic similarity categories, not verified probabilities of ownership.

### Graphical Representation

Display a bar chart showing the contribution of every attribute.

Show the complete score calculation.

# 9. TOPIC 4: BRUTE FORCE VS. HEURISTIC APPROACHES

Implement two independent candidate-search algorithms.

## Algorithm A: Brute Force

For a selected lost report:

1. Retrieve all found reports.
2. Apply mandatory validity checks.
3. Calculate similarity for every eligible candidate.
4. Rank all candidates.
5. Return the Top-K matches.

Do not use optional category or location prefiltering.

This is an exhaustive candidate-search baseline.

## Algorithm B: Optimized Heuristic Search

For the same lost report:

1. Retrieve active found reports.
2. Apply category-based filtering.
3. Use relevant location and date compatibility checks.
4. Calculate similarity scores.
5. Rank candidates.
6. Return Top-K matches.

Allow users to disable strict filters or broaden the search.

### Fair Comparison

Both algorithms must use the same weighted similarity formula.

The primary difference should be the number of candidates evaluated.

### Performance Metrics

Calculate:

* Total candidate reports
* Candidates evaluated
* Similarity calculations
* Execution time
* Highest score
* Number of recommendations
* Candidate reduction percentage

### Formula

Reduction (%) = ((B - H) / B) × 100

Where:

* B = Brute-force similarity comparisons
* H = Heuristic similarity comparisons

Handle B = 0 safely.

### Important

Do not fabricate execution times.

Use Python's `time.perf_counter()`.

For benchmarks:

* Use identical datasets.
* Perform warm-up runs.
* Repeat measurements.
* Report median execution time.
* Explain that optimized filtering may miss relevant candidates.

### Graphs

# 10. TOPIC 5: CONDITIONAL STATEMENTS

Implement explicit matching rules.

A valid candidate must satisfy:

1. The selected report must be a lost report.
2. The candidate must be a found report.
3. Both reports must be active.
4. Reports must have different IDs.
5. Date compatibility must be evaluated.

Example:

```python
def is_valid_candidate(lost_item, found_item):
    if lost_item.id == found_item.id:
        return False

    if lost_item.type != "lost":
        return False

    if found_item.type != "found":
        return False

    if lost_item.status != "active":
        return False

    if found_item.status != "active":
        return False

    return True
```

Extend this function with date validation.

If the found date is earlier than the lost date, flag the inconsistency.

Use a configurable tolerance for uncertain dates, rather than silently accepting impossible timelines.

# 19. PERFORMANCE METRICS

The system must calculate:

### 1. Execution Time

Measure algorithm runtime in milliseconds.

### 2. Candidate Reduction

Reduction (%) = ((B - H) / B) × 100

### 3. Highest Similarity Score

Maximum score among eligible candidates.

### 4. Average Similarity Score

Average score among evaluated candidates.

### 5. Number of Potential Matches

Count candidates above the configured threshold.

### 6. Matching Recall on Labelled Demo Data

Recall = True Positives / (True Positives + False Negatives)

### 7. Matching Precision on Labelled Demo Data

Precision = True Positives / (True Positives + False Positives)

Calculate precision and recall only when a dataset contains known ground-truth matches.
